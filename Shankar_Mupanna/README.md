# 🚗 Car Rental & Fleet Booking System API

A production-ready Car Rental & Vehicle Fleet Management API built with **Node.js**, **Express.js**, and **Supabase** (PostgreSQL Cloud Database & Supabase Auth).

---

## 📌 Features & Highlights

- 🔐 **Supabase Authentication**: Secure user registration, login, and JWT access token verification (`Authorization: Bearer <token>`).
- 🚗 **Vehicle Fleet Management**: CRUD operations for fleet vehicles, query filtering by `category` and `status`, and relational fetching of vehicle rental history.
- 📅 **Date Range Overlap Prevention**: Advanced interval collision detection prevents double-booking of vehicles (`(start_date <= existing_end) AND (end_date >= existing_start)`).
- 💰 **Automated Billing Computation**: Dynamic total cost calculation based on calculated day span and vehicle daily rates (`days * daily_rate`).
- 🔄 **Fleet Availability State Machine**: Automatic state updates transition vehicles through `available` ➔ `rented` ➔ `maintenance` ➔ `available` states upon booking, completion, or cancellation.
- 📋 **Postman Collection Included**: Complete Postman collection for automated testing and API verification.

## 🗄️ Database Schema & Setup

Execute the following script in your **Supabase SQL Editor**:

```sql
-- 1. Vehicles Table
CREATE TABLE IF NOT EXISTS vehicles (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    brand TEXT NOT NULL,
    model TEXT NOT NULL,
    year INT NOT NULL,
    category TEXT NOT NULL CHECK (category IN ('Sedan', 'SUV', 'Luxury', 'Hatchback', 'Electric')),
    daily_rate NUMERIC(10, 2) NOT NULL CHECK (daily_rate > 0),
    fuel_type TEXT NOT NULL,
    seating_capacity INT NOT NULL DEFAULT 5,
    status TEXT NOT NULL DEFAULT 'available' CHECK (status IN ('available', 'rented', 'maintenance')),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. Rentals / Bookings Table
CREATE TABLE IF NOT EXISTS rentals (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id UUID NOT NULL, -- references Supabase auth.users
    vehicle_id BIGINT REFERENCES vehicles(id) ON DELETE RESTRICT,
    customer_name TEXT NOT NULL,
    customer_email TEXT NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    total_cost NUMERIC(10, 2) NOT NULL,
    status TEXT NOT NULL DEFAULT 'booked' CHECK (status IN ('booked', 'active', 'completed', 'cancelled')),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    CONSTRAINT valid_date_range CHECK (end_date >= start_date)
);

-- Performance index for reservation date queries
CREATE INDEX IF NOT EXISTS idx_rentals_vehicle_dates 
ON rentals (vehicle_id, start_date, end_date) 
WHERE status IN ('booked', 'active');
```

## 📋 API Endpoints Specification

### 🔐 Supabase Auth Endpoints

| Method | Endpoint | Description | Auth Required | Status Codes |
|---|---|---|---|---|
| `POST` | `/api/auth/register` | Register customer with Supabase Auth | No | `201 Created`, `400 Bad Request` |
| `POST` | `/api/auth/login` | Login and receive Supabase Bearer token | No | `200 OK`, `401 Unauthorized` |

#### Auth Request Examples

**Register (`POST /api/auth/register`)**:
```json
{
  "email": "driver@travel.com",
  "password": "mypassword123",
  "name": "David"
}
```

**Login (`POST /api/auth/login`)**:
```json
{
  "email": "driver@travel.com",
  "password": "mypassword123"
}
```

---

### 🚗 Vehicle Fleet Management

| Method | Endpoint | Auth Required | Description | Request Body Example | Status Codes |
|---|---|---|---|---|---|
| `GET` | `/api/vehicles` | No | Fetch all vehicles (supports `?category=SUV&status=available`) | None | `200 OK` |
| `GET` | `/api/vehicles/:id` | No | Get vehicle details with past rental records | None | `200 OK`, `404 Not Found` |
| `POST` | `/api/vehicles` | Yes | Add new vehicle to fleet | `{"brand":"Tesla","model":"Model 3","year":2024,"category":"Electric","daily_rate":4500,"fuel_type":"EV","seating_capacity":5}` | `201 Created`, `400 Bad Request` |
| `PUT` | `/api/vehicles/:id` | Yes | Update vehicle daily rate or status | `{"daily_rate":4800,"status":"maintenance"}` | `200 OK`, `404 Not Found` |
| `DELETE` | `/api/vehicles/:id` | Yes | Delete vehicle from fleet | None | `200 OK`, `400 Has Active Bookings` |

---

### 📅 Rental & Booking Operations

| Method | Endpoint | Auth Required | Description | Request Body Example | Status Codes |
|---|---|---|---|---|---|
| `POST` | `/api/rentals` | Yes | Book a vehicle (Checks date collisions & computes total cost) | `{"vehicle_id":1,"start_date":"2026-05-01","end_date":"2026-05-05","customer_name":"David","customer_email":"david@test.com"}` | `201 Created`, `400 Collision/Error` |
| `GET` | `/api/rentals/my-bookings` | Yes | List rentals for authenticated user | None | `200 OK` |
| `PATCH` | `/api/rentals/:id/cancel` | Yes | Cancel upcoming rental | None | `200 OK`, `400 Cannot Cancel` |
| `PATCH` | `/api/rentals/:id/complete` | Yes | Mark car as returned (Sets vehicle status back to `available`) | None | `200 OK` |

## 🧪 Testing & Date Overlap Collision Verification

1. Configure `.env` with valid Supabase credentials and execute `schema.sql` in Supabase.
2. Insert 3 vehicles into the `vehicles` table.
3. Book Vehicle #1 for dates `2026-05-01` to `2026-05-05`:
   - Returns `201 Created` with dynamic billing calculation: `4 days * daily_rate`.
4. Try booking Vehicle #1 again for dates `2026-05-03` to `2026-05-07`:
   - The server rejects the request with `400 Bad Request`:
   ```json
   {
     "success": false,
     "message": "Vehicle already reserved during this timeframe"
   }
   ```
5. Import `itm-assignment-10-car-rental-api.postman_collection.json` into Postman to execute all test cases.
